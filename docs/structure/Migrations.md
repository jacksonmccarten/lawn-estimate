# Migrations

`packages/db/migrations` is append-only: the runner records each file name in `schema_migrations` and skips it afterwards, so an edit to an existing file never reaches a database that already ran it. Behavior changes with a new numbered file, and every migration is backward-compatible with the code already deployed. Two runners apply them: `migrate.ts` over node-postgres (local, CI) and `migrateStatements` one statement at a time over the Data API (the `migrate` Lambda, see [[Lambdas]]); a test builds a database each way and compares the results.

| # | File | What it adds |
| --- | --- | --- |
| 0001 | `roles` | `app_rw`, `app_public`, `app_definer`: NOLOGIN, no superuser, no BYPASSRLS, no table ownership. Guarded, since roles are cluster-wide |
| 0002 | `schema` | The `btree_gist` extension and the first thirteen tables (see [[Data Model]]); composite foreign keys that keep a child's `company_id` equal to its parent's; triggers that make a published pricing version and its services and tiers immutable (SQLSTATE `55000`) |
| 0003 | `rls` | `current_company_id()`; `ENABLE` + `FORCE ROW LEVEL SECURITY` and a policy on every company-scoped table; grants to `app_rw`; `app_definer`'s own `SELECT` policies; the `public_company_profile` view and `company_id_for_sub(sub)` |
| 0004 | `seed_pa` | `service_catalog` with taxable flags per 61 Pa. Code § 55.6 and `tax_rates` for all 67 counties (6%, Allegheny 7%, Philadelphia 8%). Snow removal is deliberately absent until its taxability is verified (R5) |
| 0005 | `public_entry` | Revokes the default `EXECUTE` to `PUBLIC`, for existing functions and every future one, so a function is callable only by roles it is granted to |
| 0006 | `zip_county` | One row per Pennsylvania ZCTA with its primary county (largest land share) and `county_for_zip(zip)`. Census 2020 relationship file |
| 0007 | `zip_county_parts` | Every county a zip has land in, and `counties_for_zip(zip)` returning each with its current rate in basis points, primary first |
| 0008 | `lead_decision_final` | A lead is decided once: a trigger raises SQLSTATE `LQ001` on a second decision, for every role; a check constraint keeps an adjusted total off anything but an accepted lead |
| 0009 | `public_estimate_submit` | Everything `/estimate` and `/submit` need as `app_public`: new columns (`companies.phone`, `alert_email`, `alert_phone`, `regrid_lookup_quota`; `quotes.original_grass_sqft`; `leads.sms_sent_at`; `parcel_cache.state`, `zip`), `app_definer` policies on `quotes`, `leads`, `usage_meters` and `pricing_tiers`, the helpers `origin_allowed` and `usage_month`, and the SECURITY DEFINER functions granted to `app_public`: `estimate_context`, `regrid_reserve_lookup`, `parcel_cache_put`, `estimate_pricing_input` (over `pricing_slice`), `estimate_insert_quote`, `estimate_quote_for_adjust`, `estimate_apply_adjustment`, `submit_lead`, `lead_mark_notified` |
| 0010 | `public_allowed_origins` | `company_allowed_origins(slug)`, for the widget page's `frame-ancestors` |
| 0011 | `quote_origin_drawn` | `drawn` becomes a valid `quotes.origin`: the homeowner outlined the lawn on an aerial photo |
| 0012 | `signup` | `create_company_for_sub(sub, name, email)`: a login's own company, membership, starting service area (every PA county in group `standard`) and trial allowance; `app_definer` insert policies on `companies`, `company_members`, `service_regions` |
| 0013 | `allowance_counts_estimates` | `estimate_context` now compares the allowance with estimates priced this month (`usage_meters.quotes`), since Regrid lookups are never made. `regrid_lookup_quota` keeps its name |
| 0014 | `zip_centroid` | The centre point of each Pennsylvania zip (Census 2023 gazetteer), for "within so many miles of here" |
| 0015 | `service_radius` | `companies.service_street`, `service_city`, `service_state`, `service_zip`, `service_radius_miles`: the typed business address and radius behind the service area screen |
| 0016 | `questionnaire` | `companies.questionnaire` (jsonb): the ordered list of customer questions, seeded with five examples for every company |
| 0017 | `embed_anywhere` | `origin_allowed` accepts any origin when a company's allowlist is empty |
| 0018 | `trial_five_estimates` | The trial allowance drops from 50 to 5 estimates a month, for new companies and for existing companies still at 50 |

The three zip-code files (0006, 0007, 0014) are generated by the Python scripts in `packages/db/scripts` from Census Bureau files and are each over 1,800 lines; `splitStatements` cuts their long INSERTs into pieces under the Data API's limit. A function owned by `app_definer` is replaced as that role (0013, 0018), and every new function needs an explicit `GRANT EXECUTE` before it is handed over.
